# 4 minute 30 second demo outline

Record the real Electron app after live setup and acceptance testing. Do not present the hosted simulated UI as live provider evidence.

0:00–0:30 — Introduce a hands-busy researcher revisiting project notes. Show Electron, installed Qwen model, and configured Rime provider. Explain NOVA plans; AEGIS decides what may execute.

0:30–1:20 — Start a voice session. Ask for notes about voice continuity. Show real Rime speech, the matching memory records, and the allowed read in the audit.

1:20–2:00 — Ask NOVA to remember a new priority. Listen to the approval explanation. Show the exact payload, approve it, and observe the memory appear. Explain that the click deliberately binds approval to the content.

2:00–3:05 — Run the five-second lookup-delay case. Interrupt and change the topic to AEGIS. Keep mic and output audible in the recording. Show old work cancelled and the corrected spoken response.

3:05–3:40 — Request deletion of all memories. Show AEGIS block it. Deliberately disable one provider; show the disclosed failure and typed recovery path without claiming Rime remains active.

3:40–4:15 — Show per-trial acoustic measurements, the exact Rime configuration, and exported audit. Explicitly separate acoustic data from the web simulation and request timers.

4:15–4:30 — State limitations: headset conditions, English STT defaults, no arbitrary computer tools, no word-level partial-hearing reconstruction. Link the repository and evidence.

Do not invent results if the live acceptance target is missed. Show the failure, report the measured result, and describe the remaining work.
